# BIL-023 : Front US8 : salle d'attente virtuelle

- **Branche** : `feat/bil-023-front-file-attente` (empilée sur `feat/bil-015-file-attente`,
  chaîne #42 ← … ← #55 ; compte GitHub verrouillé ; PR avec base `feat/bil-015-file-attente`)
- **Dépend de** : BIL-015, BIL-020
- **Service** : frontend

## Objectif

En tant que client, je veux voir ma position dans la file d'attente et être admis
automatiquement à mon tour.

## Étapes

- [ ] Écran d'attente avec position et estimation.
- [ ] Interrogation périodique raisonnable, redirection vers le plan de salle à l'admission.
- [ ] Jeton d'admission transmis à l'API (`creerCommande`, en-tête `X-Admission-Token`).

## Critères d'acceptance

| #   | Critère                                        |
| --- | ---------------------------------------------- |
| CA1 | Rafraîchir la page ne fait pas perdre sa place |

## Contraintes

- Pas d'interrogation plus fréquente que toutes les quelques secondes.

## Décisions

- Mode allégé (2026-11-14) : pas de nouveaux tests, review en passe finale.
- L'admission est vérifiée par Commandes (BIL-015) : le jeton est envoyé sur `creerCommande`,
  pas sur une route de verrouillage de Billets.
- Le front ne sait pas d'avance si une séance est sous file : il tente `entrerFile` ;
  404 `QUEUE_NOT_FOUND` → plan de salle direct ; sinon salle d'attente E16.
- Jeton d'admission en mémoire de l'onglet seulement (CA1 tenu par l'idempotence serveur).
  Interrogation toutes les 5 à 30 s (quart de l'attente estimée). File en panne (autre que 404)
  sur E03 : réservation laissée possible, le serveur décide. Retour d'E16 vers la fiche
  événement. Non traité : admission qui expire pendant un `creerCommande` en cours.
