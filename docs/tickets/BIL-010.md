# BIL-010 : US5 : libérer les places des commandes non payées

- **Branche** : `feat/bil-010-expiration` (empilée sur `feat/bil-009-emission-billets`,
  elle-même sur `feat/bil-008-commande-paiement` ; dérogation du développeur du 2026-11-12,
  compte GitHub verrouillé ; PR avec base `feat/bil-009-emission-billets`)
- **Dépend de** : BIL-008
- **Service** : commandes, billets

## Objectif

En tant que client, je veux qu'une place abandonnée par quelqu'un d'autre redevienne
disponible, afin de pouvoir l'acheter.

## Étapes

- [ ] Tâche périodique dans Commandes : les commandes en attente dépassées passent en expirées.
- [ ] Publication de `ticketing.order.expired` via l'outbox.
- [ ] Billets consomme l'événement et libère les places.
- [ ] Éviter l'exécution en double quand Commandes a deux instances (verrou Redis sur la tâche).

## Critères d'acceptance

| #   | Critère                                                                      |
| --- | ---------------------------------------------------------------------------- |
| CA1 | Une commande non payée expire après le délai et ses places redeviennent libres |
| CA2 | Avec deux instances, la tâche ne s'exécute qu'une fois par cycle              |

## Contraintes

- Délai d'expiration en configuration, raccourci dans les tests.

## Décisions (validées d'avance, recommandations)

- Aucune route HTTP : pas d'étape contrat.
- Plan (`docs/test-plans/BIL-010.md`) : recommandations Q1-Q6 et hypothèses H1-H6 retenues.
  Échéance = `expire_le` ; la tâche relit `expire_le <= maintenant` sous `FOR UPDATE` (H3 :
  `payerCommande` repousse `expire_le`, sinon expiration en plein paiement) et réutilise la
  logique d'expiration de BIL-008 (lecture Paiements). `EXPIRATION_PERIODE` 30 s ; verrou Redis
  `commandes:tache:expiration` de la durée d'une période, non relâché ; Redis injoignable :
  cycle sauté. Billets (`billets.order-expired`) libère les verrous dans le traitement (une
  panne Redis repart en nouvel essai). Lot de 100 par `expire_le` croissant. Commande sans
  `expire_le` : hors périmètre, limite écrite dans le README.
- Squelette : `REDIS_URL` gardé facultatif jusqu'à l'étape tests (H6 : obligatoire ensuite) ;
  index `(statut, expire_le)` sur `commandes` par une nouvelle migration à l'implémentation.
- Tests d'intégration : écarts acceptés (paiement simultané : 409 `ORDER_NOT_PENDING` ou
  `SEAT_ALREADY_TAKEN` ; `expire_le` forcé par `UPDATE` ; période de 10 s pour le test du verrou
  non relâché). À l'implémentation : `VerrouTacheRedis` ne doit pas lever à la construction ;
  la tâche lit le client Paiements dans `app.state` à chaque cycle (remplaçable en test).
