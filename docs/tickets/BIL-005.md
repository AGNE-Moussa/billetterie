# BIL-005 : Cache Redis du catalogue

- **Branche** : `feat/bil-005-cache`
- **Dépend de** : BIL-004
- **Service** : catalogue

## Objectif

Servir les lectures du catalogue depuis Redis pour encaisser le pic et rester disponible si la
base ralentit.

## Étapes

- [ ] Cache-aside sur les lectures, durée de vie courte.
- [ ] Invalidation à chaque modification admin.
- [ ] Si la base ne répond pas, servir la dernière valeur en cache avec un en-tête qui le signale.

## Critères d'acceptance

| #   | Critère                                             |
| --- | --------------------------------------------------- |
| CA1 | Une modification admin est visible immédiatement    |
| CA2 | Base arrêtée : la lecture renvoie 200 depuis le cache |

## Contraintes

- Les places disponibles ne sont jamais mises en cache ici (elles viennent de Billets).

## Décisions (validation du contrat, 2026-11-01)

- Q1 : en-tête `X-Cache-Stale: true` sur la réponse 200.
- Q2 : seulement en mode dégradé (base injoignable) ; absent sur un hit normal.
- Q3 : les 7 lectures publiques ; `/health` exclu (503 si la base tombe).
- Q4 : pas d'en-tête `Age`.
- Q5 : seuls les 200 sont mis en cache ; un 404 n'est jamais servi depuis le cache.
- Q6 : forme propre au catalogue, rien dans `docs/conventions.md`.
- Q7 : deux copies en cache : fraîcheur 30 s (cache-aside), copie de secours 24 h lue seulement
  si la base ne répond pas.
- Q8 : une modification admin supprime les deux copies (fraîcheur et secours).
- Q9 : aucun champ de disponibilité des places dans ce ticket.
