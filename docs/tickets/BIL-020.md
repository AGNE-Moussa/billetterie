## Objectif

En tant que client, je veux choisir mes places sur un plan de salle et voir combien de temps
elles me sont réservées.

## Étapes

- [ ] Plan de salle (SVG ou grille) avec états libre, verrouillée, vendue, sélectionnée.
- [ ] Verrouillage au clic ; message clair sur `SEAT_ALREADY_TAKEN` et rafraîchissement du plan.
- [ ] Compte à rebours du verrou, libération à l'expiration.
- [ ] Tests de composants du plan (reportés : mode allégé).

## Critères d'acceptance

| #   | Critère                                                            |
| --- | ------------------------------------------------------------------ |
| CA1 | Une place prise par un autre client est signalée sans casser la page |
| CA2 | Le plan est navigable au clavier                                   |

## Contraintes

- Le compte à rebours suit l'expiration renvoyée par l'API, pas une horloge locale arbitraire.

## Décisions

- Mode allégé (2026-11-14) : pas de nouveaux tests, review en passe finale.
- Q1 de BIL-018, tranchée par le développeur : `carte_test` devient facultatif dans
  `creerCommande`. Sans carte : 201 `EN_ATTENTE` avec `expire_le` (places verrouillées), le
  front affiche le compte à rebours puis le client paie par `payerCommande`. Avec carte :
  comportement actuel (appel unique, revendeurs). Contrat modifié dans ce ticket.
- Contrat (3 fichiers identiques : service, cible, partenaires) : `carte_test` en
  `str | None` (défaut null, `null` explicite = sans carte) ; 402 et 503 Paiements seulement
  avec carte ; un revendeur peut aussi commander sans carte ; rejeu idempotent renvoie l'état
  courant ; `payerCommande` reformulée (paiement normal d'une commande en attente).
- `default: null` retiré de `carte_test` dans les trois contrats (FastAPI ne l'émet pas).
  Test existant adapté : cas `sans_carte` retiré de
  `test_un_corps_de_commande_invalide_renvoie_422` (sans carte n'est plus un 422).
- Après paiement, E04 renvoie vers `/commandes/:id` (E05, livré par BIL-021). Limites : temps
  restant calculé sur l'horloge du navigateur ; plafond de 10 places par commande côté front,
  `TICKET_LIMIT_EXCEEDED` affiché si le plafond par séance est atteint.
- Q5 de BIL-018 : trois états de place à l'écran (libre, indisponible, sélectionnée), l'API ne
  donnant que `disponible`.
