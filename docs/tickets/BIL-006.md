# BIL-006 : US2 : verrouiller une place pendant l'achat

- **Branche** : `feat/bil-006-verrou-places`
- **Dépend de** : BIL-004
- **Service** : billets

## Objectif

En tant que client, je veux que la place choisie me soit réservée quelques minutes, afin de payer
sans me la faire prendre.

## Étapes

- [ ] Générer le service `billets` ; tables places (par séance) et billets.
- [ ] Route de verrouillage : `SET NX` avec expiration, identifiant du client en valeur.
- [ ] Statuts de place : libre, verrouillée, vendue ; contrainte unique sur (séance, place) pour
  les billets vendus.
- [ ] Route de disponibilité par séance.
- [ ] Refus `SEAT_ALREADY_TAKEN` (409) si la place est prise.

## Critères d'acceptance

| #   | Critère                                                  |
| --- | -------------------------------------------------------- |
| CA1 | Une place verrouillée est refusée à un autre client (409) |
| CA2 | Le verrou expire seul après la durée fixée               |
| CA3 | Seul le détenteur du verrou peut le lever                |

## Contraintes

- Durée du verrou en configuration (valeur par défaut 10 minutes).

## Décisions (validation du contrat, 2026-11-02)

Recommandations retenues par le développeur (délégation des validations) :

- Q1 : le propriétaire du verrou est la commande (`commande_id`), pas le client (contrat cible).
- Q2 : pas de route de libération ; la libération compare-puis-supprime (Lua) est une fonction du
  dépôt, CA3 est prouvé par des tests (une autre commande ne lève pas le verrou, le détenteur oui)
  et, côté HTTP, par le 409 d'une confirmation demandée par une autre commande.
- Q3 : `PUT /api/v1/seats/{place_id}/lock` réservé au client `services` (scope `seats:lock`) ;
  « un autre client » de CA1 = une autre `commande_id`.
- Q4 : `confirmation: true` implémentée dès ce ticket (durée de confirmation 1 h par défaut).
- Q5 : le consommateur idempotent `ticketing.show.scheduled` (création des places, numéros de 1 à
  `nombre_places` par rang) fait partie de ce ticket.
- Q6 : préfixe public `GET /api/v1/seats` dans `ROUTES_PUBLIQUES` ; `/api/v1/seats/health` est
  donc public, comme catalogue (mention dans `docs/conventions.md`).
- Q7 : pas d'énumération de statut ; le contrat expose `disponible` (ni verrou, ni billet).
- Q8 : `DUREE_VERROU_RESERVATION` (600 s) et `DUREE_VERROU_CONFIRMATION` (3600 s), en secondes.

Écarts avec la page Notion (valeur du verrou, statuts, CA3) : la page n'est pas modifiée ; ce
fichier et le contrat font foi.
