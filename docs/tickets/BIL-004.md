# BIL-004 : US1 : consulter les événements et leurs séances

- **Branche** : `feat/bil-004-catalogue`
- **Dépend de** : BIL-002, BIL-003
- **Service** : catalogue

## Objectif

En tant que visiteur, je veux parcourir les événements, leurs lieux et leurs séances, afin de
choisir un spectacle.

## Étapes

- [ ] Partir du squelette `catalogue` créé en BIL-001.
- [ ] Tables événements, lieux, séances et catégories, migration Alembic.
- [ ] Routes publiques de lecture (liste paginée, détail, filtre par date et catégorie).
- [ ] Routes admin de création et modification (scope `events:write`).
- [ ] Jeu de données de démonstration.

## Critères d'acceptance

| #   | Critère                                                              |
| --- | -------------------------------------------------------------------- |
| CA1 | Les routes respectent le contrat OpenAPI (test en CI)                |
| CA2 | Un client sans `events:write` ne peut pas créer d'événement (403)    |
| CA3 | Le service est joignable via Traefik et visible dans Consul          |

## Contraintes

- Pagination obligatoire sur toute liste.

## Décisions (validation du contrat, 2026-10-29)

- Q1 : l'annulation de séance (`annulerSeance`) reste hors périmètre, elle relève de BIL-011.
- Q2 : pas de route de modification (PUT/PATCH) ; le contrat cible BIL-002 fait foi.
- Q3 : pas de filtre par catégorie ; les filtres `du`, `au`, `ville`, `q` du contrat cible suffisent.
- Q4 : le détail d'un événement reste sans lieu ni séances, comme dans le contrat cible.
- Q5 : `creerSeance` publie `ticketing.show.scheduled` via l'outbox (`libs/commun/outbox.py`), dans
  la même transaction que la séance.
- Q6 : le cache Redis relève de BIL-005 ; ici, base injoignable donne 503 `BASE_INDISPONIBLE`.
- CA3 : ajouter le préfixe `shows` aux tags Traefik et à `ROUTES_PUBLIQUES` du vérificateur.
