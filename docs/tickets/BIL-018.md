## Objectif

Décrire les parcours et les écrans du front billetterie avant d'en coder un seul.

## Étapes

- [ ] Parcours visiteur, client, organisateur (diagramme Mermaid).
- [ ] Liste des écrans, avec pour chacun les données affichées et les routes d'API appelées.
- [ ] Maquettes basse fidélité de chaque écran dans `docs/front/`.
- [ ] Plan des routes React et des rôles autorisés.

## Critères d'acceptance

| #   | Critère                                              |
| --- | ---------------------------------------------------- |
| CA1 | Chaque user story a son écran et son parcours        |
| CA2 | Chaque écran indique les routes d'API qu'il appelle  |

## Contraintes

- Maquettes simples : la structure compte, pas le pixel.

## Décisions

- Mode allégé (2026-11-14). Ticket de conception : rédigé par un agent généraliste (aucun agent
  du pipeline n'écrit dans `docs/front/`).
- Livrables : `docs/front/parcours.md`, `docs/front/ecrans.md` (E01 à E16), `docs/front/routes.md`.
- Retenus : R1 à R3 (catalogue sur `/`, chemins en français, `/seances/:seanceId`), Q3 à Q7
