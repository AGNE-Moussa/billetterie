- Ticket : `docs/tickets/BIL-012.md` ; contrats : `docs/contrats/partenaires.yaml` (documentation
  publiée), `services/commandes/openapi.yaml`, `services/catalogue/openapi.yaml`,
  `services/billets/openapi.yaml` (inchangés, décision « Contrat »)
- Niveaux : unitaire, intégration (dont deux cas `smoke` joués par `make test-smoke` contre la
  plateforme démarrée, seul moyen réaliste de rejouer Postman et Keycloak de bout en bout, comme
  `tests/smoke/test_places.py` et `scripts/pannes.sh`)

## Questions

> **Réponses (2026-11-13)** : les quatre recommandations ci-dessous sont retenues telles quelles
> (délégation du développeur). Hypothèses H1 à H8 validées. Aucune question ouverte.

1. **Nom de l'hôte partenaires (Q1).** Le ticket fixe un hôte dédié mais pas son nom.
   Recommandation : variable `HOTE_PARTENAIRES`, `partenaires.localhost` en local et
   `partenaires.<domaine>` en démo ; alias réseau du même nom sur le conteneur Traefik (Newman le
   joint par son nom, sans surcharger l'en-tête `Host`) ; les tests pytest envoient l'en-tête
   `Host`.
2. **Jeton sans rôle `partner` sur l'hôte partenaires.** Q2 refuse `partner` sur la chaîne
   `standard`, mais rien n'est dit du cas inverse (jeton `customer`, `admin` ou `services` sur la
   chaîne `partenaires`). Recommandation : refuser aussi, `403 ROLE_MANQUANT` ; l'hôte et sa
   documentation ne servent que les revendeurs, et les routes publiques restent accessibles sans
   jeton.
3. **Canal des commandes existantes (migration).** La nouvelle colonne doit être remplie pour les
   lignes déjà en base. Recommandation : migration `0005`, `canal = 'PARTENAIRE'` si
   `email IS NULL` (modèle de données : « NULL pour un revendeur »), `'DIRECT'` sinon, puis
   `NOT NULL` sans `server_default` (le code fixe toujours le canal) et contrainte nommée
   `ck_commandes_canal` (`IN ('DIRECT', 'PARTENAIRE')`).
4. **Jeton qui porte à la fois `customer` et `partner`.** Le realm ne le produit pas, mais la
   règle de déduction doit être définie. Recommandation : `PARTENAIRE` dès que `partner` est
   présent, cohérent avec la gateway qui traite ce jeton comme celui d'un revendeur (Q2).

### Hypothèses retenues (réponse évidente dans les documents)

- H1. Les routeurs partenaires sont annoncés par Catalogue, Billets et Commandes seulement (les
  opérations de `partenaires.yaml`) ; Paiements et Notifications n'en ont pas.
- H2. Le quota reste compté par en-tête `Authorization` (Q1) : un nouveau jeton ouvre un nouveau
  seau. Limite connue, non testée comme un défaut.
- H3. Une route publique appelée sans jeton passe sur les deux hôtes (Q6, vérificateur
  inchangé) ; un jeton fourni est toujours vérifié, donc un jeton `partner` sur une route
  publique de l'hôte standard est refusé.
- H4. Le plafond de billets par séance (BIL-008) s'applique au revendeur comme à tout appelant ;
  aucun cas nouveau, le ticket ne le change pas.
- H5. Le `429` porte-t-il `Retry-After` ? Le ticket (Q6) le fait constater par le test de CA3 :
  le cas l'affirme ; si Traefik ne l'envoie pas, le développeur inverse l'assertion et ne le
  mentionne pas dans `partenaires.yaml`.
- H6. CA2 : le projet rejoue déjà Postman par l'image `postman/newman:6.1.3-alpine` sur le réseau
  `billetterie` (`scripts/pannes.sh`) ; la collection partenaires suit le même chemin, lancée par
  un test `smoke`.
- H7. Le canal n'est ni dans l'API ni dans les événements (Q3, « en base seulement »).
- H8. Revendeurs de test : `revendeur-test` (Keycloak, seul client du realm) pour les cas de bout
  en bout ; `R1` / `R2` (jetons `EmetteurDeTest`, sujets `service-account-revendeur-test` et
  `service-account-revendeur-test-2`) pour les cas qui exigent deux revendeurs, comme dans
  `services/commandes/tests/integration/conftest.py`. Aucun second client dans le realm.

Données communes : séance S du conftest de Commandes (catégorie Fosse à 4500 centimes, rangs A
et B), UUID générés, carte acceptée `4242424242424242`, carte refusée `4000000000000002`, client
direct A (`client.test@exemple.test`), secrets générés (`secrets.token_urlsafe`) ou lus dans
`.env` (smoke), jamais écrits.
