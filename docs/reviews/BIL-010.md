## Vérifications des priorités

- **(1) Double vente, expiration en plein paiement** : conforme. `_expirer(echue_a=...)` relit
  le statut et `expire_le` sous `FOR UPDATE` (`commandes.py:615-620`), et `expire_le` NULL est
  exclu. `payerCommande` repousse `expire_le` sous verrou de ligne avant le `POST`
  (`commandes.py:518-523`). Billets libère par `VerrousRedis.liberer`, un script Lua qui compare
  puis supprime (`billets/domaine/expiration.py:61`) : un verrou repris par une autre commande
  n'est jamais supprimé. Seul reste le verrou fantôme du point 1.
- **(2) Débit perdu** : conforme. Paiements est lu hors transaction, jamais `POST`é.
  `remboursement_du` est posé si le paiement est `ACCEPTE`, avec un journal `ERROR`
  (`commande_id` seul). Si Paiements est injoignable, la commande reste `EN_ATTENTE` sans
  interrompre le cycle (`domaine/expiration.py:55-67`).
- **(3) Tâche** : conforme. `SET NX PX` à la durée d'une période, jamais relâché
  (`infra/verrou_tache.py:33`). La construction n'ouvre aucune connexion, chaque appel est borné
  et sans nouvelle tentative, et une panne Redis saute le cycle avec un `WARNING`. L'arrêt est
  propre : `cancel` puis attente, `CancelledError` n'est pas avalée, et l'ordre LIFO de la pile
  arrête la tâche avant `verrou.fermer`. La tâche relit le client Paiements dans `app.state` à
  chaque appel.
- **(4) Idempotence de Billets** : conforme. `consommateur_idempotent`, file
  `billets.order-expired`, libération dans le traitement. Des données invalides ou une panne
  Redis lèvent une exception (trois tentatives puis DLQ), et un rejeu ne fait rien de plus
  (comparer puis supprimer).
- **(5) Migration et configuration** : conforme. 0004 a `upgrade` et `downgrade`, l'index est
  nommé et déclaré aussi dans `infra/base.py:49`. `redis_url: str` est obligatoire, et Compose
  le fournit aux deux instances par l'ancre `commandes-env`, sans secret, avec dépendance sur
  `redis` healthy.
- **(6) Sécurité, journaux** : conforme. Aucune route ajoutée. Les journaux ne contiennent que
  `commande_id`, l'identifiant de message et le nom d'instance : ni e-mail, ni jeton, ni carte.
